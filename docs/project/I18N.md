# Languages

Still Here SD is read in San Diego, where roughly a quarter of households
speak Spanish at home. A tool that plans outreach shifts in that city and
speaks only English is not finished. This document says how the second
language is built, which words were judgement calls, and exactly where
English is still on the screen.

## Scaffolding

No i18n library. A hand-rolled typed catalogue with a `useTranslation` hook,
for the same reasons this project renders PDFs with `window.print()`: the app
ships no backend and no CDN, and the runtime a library would add (message
parsing, an AST format, a plural engine, a provider tree) is larger than the
three functions actually needed. `Intl.PluralRules`, `Intl.NumberFormat`,
`Intl.DateTimeFormat` and `Intl.ListFormat` are already in every browser this
targets, and they do the parts that are genuinely hard.

| File | What it holds |
| --- | --- |
| `app/src/i18n/locale.ts` | The locale list, the `Intl` tag for each, storage. |
| `app/src/i18n/en.ts` | The English catalogue. Its keys *are* the key type. |
| `app/src/i18n/es.ts` | The Spanish catalogue, typed `Record<MessageKey, string>`. |
| `app/src/i18n/translate.ts` | Lookup, plural selection, interpolation. |
| `app/src/i18n/rich.tsx` | Inline `<b>`, `<i>`, `<c>`, `<br>` inside a message. |
| `app/src/i18n/context.ts` | `LocaleProvider`, `useTranslation`, `createTranslator`. |
| `app/src/i18n/places.ts` | Every grammatical form of the deployment's place noun. |
| `app/src/i18n/plannerText.ts` | Planner sentences and reasons, translated at display. |
| `app/src/i18n/shareText.ts` | Why a shared link was refused, translated at display. |

Four rules the scaffolding enforces rather than asks for:

1. **A key added to `en.ts` without a Spanish value is a compile error.**
   `MessageKey = keyof typeof EN_MESSAGES`, and `es.ts` is typed against it.
2. **A message is a whole sentence.** Placeholders are named (`{floor}`,
   `{area}`), and inline emphasis lives *inside* the message so a translator
   decides which words carry it. Nothing concatenates fragments.
3. **Plurals are selected, never suffixed.** `t(key, { count })` resolves
   `key.one` / `key.other` through `Intl.PluralRules` for the active locale.
4. **Numerals are formatted, never translated.** `es` maps to `es-US`, which
   writes the same digits, the same thousands separator and the same decimal
   point as `en-US`. Switching language never re-renders a figure a reader is
   checking against the artifact.

The choice persists in `localStorage` under `stillhere-locale`, beside the
existing view preference, and sets `document.documentElement.lang`. A four-line
inline script in `app/index.html` applies the stored value before the bundle
parses, so a returning Spanish reader never gets a paint of `lang="en"` —
`<html lang>` is what a screen reader picks a voice from.

## Translating what the app does not own

Three sources of user-visible text are not this workstream's to edit: the
planner (`app/src/lib/planner.ts`, `app/src/domain/planner/planner.ts`, whose
exact wording is pinned by characterization tests), the share-link validator's
refusal details, and the artifact's own `why this amount` reason strings.

All three are translated **at the display boundary**: each known sentence
shape is recognised by pattern, the numbers the producer computed are carried
across untouched, and the sentence is rebuilt from the catalogue. A shape no
rule recognises is passed through verbatim — an untranslated planner sentence
is a gap a reader can see, and a guessed one is a number that no longer means
what the planner said.

## Refusals

`app/src/refusals.test.ts` carries a Spanish rule set alongside the English
one and runs both over every chunk, plus an explicit per-locale scan of each
catalogue. This is not decoration: nothing in `es.ts` contains the word
"enforcement", so before this change a Spanish string reading *esta área
necesita desalojo* would have passed the suite in silence. Adding a locale
without adding its rules fails the suite.

The four sentences the product refuses to say are refused in both languages,
and the disclaimer exemption works in both: a forbidden shape is allowed only
inside a statement that denies it (`no`, `ni`, `nunca`, `sin`, `ningún`, …).

## Glossary — the judgement calls

A native-speaking outreach coordinator should check this list first. Where a
common translation would stigmatise, the reason is stated.

| --- | --- | --- |
| unsheltered / homeless (people) | **personas sin vivienda** | Person-first. **Never** *indigente*, *vagabundo*, *desamparado*, or *los sin techo* — all name the person by their condition or carry contempt. |
| outreach | **trabajo de calle** | What San Diego providers call it. *Alcance* reads as marketing; *acercamiento* is vaguer. |
| outreach shift | **turno de trabajo de calle** | |
| staff-hour(s) | **hora(s) de personal** | Not *hora-hombre*. |
| encampment | **campamento** | Neutral, and the word the City's own Spanish materials use. |
| displacement | **desplazamiento** | Kept only in the disclaimer that says it cannot be verified. |
| person-equivalents | **equivalentes de persona** | Deliberately clinical: the unit is not people. |
| block (city block) | **cuadra** | US/Mexican Spanish. *Manzana* is Peninsular. |
| neighborhood | **barrio** | Also `área de servicio`, `municipio`, `distrito`, `demarcación`, `sector`, `corredor`, `área` — one per profile noun, each with its own article, demonstrative and quantifier forms. |
| coverage floor / guaranteed minimum | **mínimo garantizado** (formal: *mínimo de continuidad de cobertura*) | *Piso* is a literal calque that reads as a storey. |
| planning load | **carga de planificación** | |

One deliberate two-part construction. `Every one of the 6 neighborhoods keeps
at least 8 hours.` cannot be one flat message in Spanish, because *cada uno de
los barrios* and *cada una de las áreas de servicio* disagree in gender with a
noun that is **profile data, not copy**. The quantified noun phrase is
therefore one authored catalogue entry per place noun
(`places.<noun>.everyOneOf`), and the predicate agrees with it in number only —
which is invariant across all eight nouns. Nothing else in the app splits a
sentence.

## What is still English, and why

Catalogue-authored copy is fully translated. What remains English on a Spanish
screen is text this build renders **verbatim from a source it does not own**,
marked `lang="en"` so assistive technology switches voice for it:

- The artifact's own prose: `signal.componentDistribution.interpretation`, the
  reporting-bias and robustness interpretations, `data.limitations`, the
  currency block's `headline` / `summary` / `grounds` / `promotion_rule` /
  `staleness_reason`, the forecast's model name and training window, and the
  source label. These live in `public/generated/demo.v1.json`; translating
  them belongs in the pipeline that writes them, not in the view that shows
  them, and rewriting a publisher's sentence in the view is exactly the edit
  `CurrencyPanel`'s own comment forbids.
- The organization profile's prose: `scope_statement`, `jurisdiction_note`,
  `profile_owner_role`, the geography components' `resolution_note` and
  `resolution_rule`, and the rate's `basis`. These live in `config/profiles/`.
  The schema has no per-language field; adding one is the correct fix and is
  a profile-schema change, not a view change.
- Area names (`East Village`, `Gaslamp`) — proper nouns.
- `app/index.html`'s `<meta description>`, Open Graph and JSON-LD blocks:
  static markup with one value each.

Each of these is a real gap. None of them can be closed from the view layer
without a view layer that rewrites its sources, which is a worse failure than
the gap.

## Cost

A complete second language costs **+128 kB raw / +37 kB gzip** on the bundle
(380 → 509 kB raw, 117 → 154 kB gzip), most of it the message keys, which
appear twice: once in each catalogue and once at each call site. Roughly
18 kB gzip of that could be recovered by loading the non-default catalogue
through a dynamic `import()`. It is not done, deliberately: this tool is
offline-first, and a Spanish reader with no network would get an English
interface — which is the failure this whole change exists to prevent.

## Adding a language

1. Add the tag to `LOCALES` and `INTL_LOCALE` in `i18n/locale.ts`, and a
   self-named label to `LOCALE_LABEL`.
2. Copy `en.ts` to the new file and translate. `tsc` lists every key you miss.
3. Add the language's rule set to `REFUSALS_*` in `src/refusals.test.ts`, with
   its own probes and its negation cues. The suite fails until you do.
4. Add the language's place-noun forms — every profile noun, every form.
5. Run `./scripts/verify.sh`.
