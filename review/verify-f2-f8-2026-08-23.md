# F-2 — the narrow claim propagated to the right documents, and not to the front door

**Verdict: substantially done, with one instance that matters more than the
other five combined.**

## Where it landed correctly — **verified**

The narrow form appears in exactly the four documents an adopter or evaluator
reads for commitments:

- `CHANGELOG.md`
- `docs/adoption/BRIEF.md`
- `docs/adoption/EVALUATION_CHECKLIST.md`
- `docs/project/DECISIONS.md`

`BRIEF.md:67-72` is the best version of it anywhere, and I want to be specific
about why rather than just praising it:

> Complaint volume cannot reach allocation without also corrupting the
> published forecast interval, which is derived from checksummed inputs.
>
> Not "complaint volume cannot influence planning." The narrow claim survives an
> attacker; the broad one did not.

It states the claim, states the claim it replaced, and says why — in the
document going to a board. That is the opposite of quietly editing a sentence.

## Where the broad claim is still live — **verified, six instances**

Ordered by how likely an evaluator is to read it.

**1. `README.md:80` — the front door.**

> 311 complaint volume never enters forecasting or planning — it measures
> reporting behavior, not need — and its diagnostic is shown precisely so that
> exclusion can be audited.

An evaluator reads README before BRIEF, and a funder's program officer may read
only README. This one instance undoes the propagation, because a reader who
sees the broad claim first and the narrow claim second concludes the project
walked something back quietly. **Fix this one even if you fix nothing else.**

**2. `app/src/domain/planner/types.ts:4-5` — the falsified sentence, unchanged.**

> One design decision dominates this file: **311 complaint volume is not
> representable here.**

This is the exact sentence Escalation 1 falsified, in the file `config/README.md`
points at as the authority. It is also now false a second way: Escalation 3
shows `quejas_recibidas` is representable there in Spanish.

**3. `app/src/lib/demo.ts:14`** — "Complaint volume is not representable here,
and that is enforced rather than asserted." Same sentence, same problem;
"enforced rather than asserted" is the specific part that Escalation 3 makes
untrue for Spanish.

**4. `DEVELOPMENT_PLAN.md:179`** — "Automated tests prove that 311 complaint
volume cannot enter the planning-load objective." A claim about what the tests
prove, which they do not.

**5. `app/src/domain/planner/planner.test.ts:123, 138-139`** — the `describe`
title "complaint volume cannot influence planning", and the comment "The proof
of exclusion: complaint volume has no representation in the input type." That
reasoning is exactly what Attack C disproved.

**6. `app/src/refusals.test.ts:500, 522`** — the numbered refusal and the
`describe` title, both in the broad form.

## What I judged acceptable and did **not** flag

- **`app/.oxlintrc.json`, nine messages** — "complaint volume may never
  influence planning load or allocation." This is a *prohibition addressed to a
  developer*, not a claim of impossibility. "May never" is imperative. Leave it.
- **`CONTRIBUTING.md:18`** — describes complaint volume's only permitted use.
  Accurate.
- **`DEVELOPMENT_PLAN.md:48`** — "Do not let 311 complaint volume determine
  forecast demand or outreach allocation." An instruction. Fine.

## One stale statement in the opposite direction

**`CONTRIBUTING.md:34`**: "path (`App.tsx` → `app/src/lib/planner.ts`) has no
complaint guard." That was true when written and stopped being true when
`assertNoComplaintSignal` was wired into `allocateHours`. A contributor reading
it today is told the shipped path is unguarded. Understating is safer than
overstating, but it is still wrong.

# F-8 — the portability half is fixed; the pinning half is open and honestly disclosed

## Script portability — **verified fixed**

`scripts/gen_area_outlines.py:34-35` now takes an optional argument defaulting
to a repository-relative path. Run from a clean checkout with no bundle:

```
$ python3 scripts/gen_area_outlines.py
block grid not found at data/raw/hackathon_provided/Downtown_BlockGrid.geojson
usage: python scripts/gen_area_outlines.py [path/to/Downtown_BlockGrid.geojson]
This file is part of the organizer bundle and is not in the repository.
```

Three lines, names the file, names the usage, says why it is absent. Same
message for an explicit bad path. **This is what a good failure looks like** —
the `/Volumes/A/` hardcode is gone and nobody has to guess.

## Pinning — **still open, and correctly disclosed**

`Downtown_BlockGrid.geojson` appears in neither `data/cards/checksums.sha256`
nor any file list in `scripts/fetch_raw.sh`. **Verified by grep.**

The commit message for `72b779b` says so plainly, explains that pinning needs
the organizer bundle, distinguishes provenance from privacy ("Nothing leaks —
the outlines are dissolved to area level in viewBox units"), and leaves the gap
open rather than closing it cosmetically. I have no criticism of the handling;
the gap is real and is now documented in the place a reader will find it.

## Illustrative status in the UI — **partially visible**

The brief asked whether the map's illustrative status is visible in the UI and
not only in the brief. Both halves of the answer are true:

**Visible.** `GeographyProvenance` is rendered from
`features/planner/PlannerSection.tsx:175`. It lists each geography component
(area list, boundaries, adjacency) with its `resolution_status` and the
profile's `resolution_note`, and separately names any area the loaded artifact
carries no observation for. For San Diego, boundaries and adjacency show as
unresolved with the profile's full sentence explaining what that costs. This is
real, in-product disclosure and it is better than most projects manage.

**Not on the map.** The map's own captions read:

```
map.captionPlanned:   "Planned staff-hours by neighborhood · simplified neighborhood boundaries"
workspace.captionTail: " · simplified neighborhood boundaries · not a count of people"
```

"Simplified neighborhood boundaries" reads as *simplified from a real boundary*.
The actual state is *drawn from a file with no verifiable provenance, dissolved
to area level.* A reader looking at the map sees a word that implies a source;
the disclosure that there is no source is in a `<details>` element in a
different section.

**Suggested wording** (not applied): "schematic area outlines · not a surveyed
boundary" in the caption, with the existing `GeographyProvenance` disclosure
carrying the detail. The brief already uses the right word — "the map is an
illustration rather than a verified boundary" — and the caption should match
the brief.
